# TOMS Notion 実構築マニュアル（初心者向け）

> **Phase 1.6 — ボタン単位の構築手順**  
> Notion 未経験者でも半日で TOMS 業務管理システムを構築できる手順書  
> 最終更新: 2026-05-31

---

## このマニュアルの使い方

1. [notion_build_checklist.md](./notion_build_checklist.md) と並行して使う
2. 各 DB は **この順番** で作る: 顧客 → 案件 → 現調 → 単価 → 見積 → 請求 → 工事写真 → 見積ライブラリ → ダッシュボード
3. `[📸 スクショ]` の位置で画面キャプチャを撮り、後から見返せるように保存する
4. 詳細設計は [notion_database_design.md](./notion_database_design.md) を参照（新規設計書は作らない）

## 第0章: Notion 基本操作

### 0-1. データベースを新規作成する

1. 左サイドバーで対象フォルダ（例: `マスター`）をクリック
2. フォルダ内の **＋ New page** をクリック
3. ページタイトルを入力（例: `顧客マスターDB`）
4. 本文エリアで `/table` と入力
5. 表示される候補から **Table - Full page** をクリック
6. ページ全体がテーブル DB になる

> **[📸 スクショ]** `/table` 入力時の候補一覧  
> 保存先: `screenshots/00_table_create.png`

### 0-2. プロパティ（列）を追加する

1. テーブル右上の **「＋」** をクリック
2. 追加したい型（Text / Select / Number 等）をクリック
3. プロパティ名を入力
4. **Done** または Enter で確定

> **[📸 スクショ]** プロパティ型選択メニュー  
> 保存先: `screenshots/00_property_types.png`

### 0-3. プロパティ名を変更する

1. 列ヘッダー（例: `Name`）をクリック
2. **Edit property** をクリック
3. 名前欄を変更 → **Done**

## 第1章: プロパティ型の設定方法

### 1-1. Select（選択肢）の作り方

**用途**: 顧客区分、工事分類、案件状態 など

#### 手順

1. **「＋」** → **Select** をクリック
2. プロパティ名を入力（例: `顧客区分`）
3. 列ヘッダーをクリック → **Edit property**
4. **Add an option** をクリック
5. 選択肢名を 1 つずつ入力（Enter で確定）
6. 色アイコンをクリックして色を変更（任意）
7. **Done**

#### 顧客区分の選択肢（コピペ用）

```
一般
管理会社
元請A
元請B
工務店
法人
```

#### 工事分類の選択肢（全 DB で統一）

```
換気
照明
コンセント
スイッチ
分電盤
エアコン
防犯カメラ
LAN
Wi-Fi
アンテナ
インターホン
EV
その他
```

> **[📸 スクショ]** Select 選択肢編集画面  
> 保存先: `screenshots/01_select_options.png`

#### Multi-select（複数選択）の作り方

1. **「＋」** → **Select** ではなく **Multi-select** を選択
2. 以降は Select と同じ手順で選択肢を追加

### 1-2. Relation（関連）の作り方

**用途**: 案件 ↔ 顧客、見積 ↔ 現調項目 など DB 間のリンク

#### 手順

1. **「＋」** → **Relation** をクリック
2. **Select a database** でリンク先 DB を検索・選択  
   例: 案件管理DB から顧客マスターDB へリンクする場合 → `顧客マスター` を選択
3. **Show on [相手DB名]** を **ON** にする（双方向リンク）
4. 逆方向のプロパティ名を確認（自動入力で OK、変更も可）  
   例: 顧客マスター側に `関連案件` が自動作成される
5. **Done**

> **[📸 スクショ]** Relation 設定画面（双方向 ON）  
> 保存先: `screenshots/02_relation_setup.png`

#### よくある Relation 設定

| 設定元 DB | プロパティ名 | リンク先 DB | 逆方向名 |
|----------|------------|------------|---------|
| 案件管理DB | 顧客名 | 顧客マスターDB | 関連案件 |
| 現調DB | 案件 | 案件管理DB | 現調 |
| 見積DB | 案件 | 案件管理DB | 見積 |
| 見積DB | 工事項目 | 現調DB | 見積 |
| 請求DB | 案件 | 案件管理DB | 請求 |
| 請求DB | 見積 | 見積DB | 請求 |

#### ポイント

- Relation は **先にリンク先 DB が存在** している必要がある
- 双方向 ON にすると、相手 DB からも逆引きできる
- CSV インポートでは Relation は設定できない（手動リンクが必要）

---

### 1-3. Rollup（集計）の作り方

**用途**: 関連 DB の値を参照・集計（顧客区分の取得、見積金額の合計 等）

#### 手順

1. **「＋」** → **Rollup** をクリック
2. プロパティ名を入力（例: `顧客区分`）
3. **Relation** ドロップダウン: 参照に使う Relation プロパティを選択  
   例: 案件管理DB の `顧客名` Relation
4. **Property** ドロップダウン: 相手 DB のどのプロパティを取得するか選択  
   例: `顧客区分`
5. **Calculate** ドロップダウン: 集計方法を選択

#### Calculate の選び方

| 目的 | Calculate 設定 |
|------|---------------|
| 値をそのまま表示 | **Show original** |
| 件数を数える | **Count all** |
| 合計する | **Sum** |
| 最新の日付 | **Latest date** |
| 最古の日付 | **Earliest date** |

#### 設定例: 案件管理DB の顧客区分

```
プロパティ名: 顧客区分
Relation:     顧客名
Property:     顧客区分
Calculate:    Show original
```

#### 設定例: 見積DB の小計

```
プロパティ名: 小計
Relation:     工事項目
Property:     見積金額
Calculate:    Sum
```

> **[📸 スクショ]** Rollup 設定画面（Relation / Property / Calculate）  
> 保存先: `screenshots/03_rollup_setup.png`

#### トラブルシューティング

| 症状 | 原因 | 対処 |
|------|------|------|
| Rollup が空 | Relation が未設定 | 先に Relation で顧客/案件を選択 |
| 顧客名が表示されない | Property で Relation 型を選んでいる | 相手 DB の Title 型プロパティを選ぶ |
| Sum が 0 | 関連レコードがない | 工事項目を見積にリンク |

### 1-4. Formula（計算式）の作り方

**用途**: 見積単価・税込合計・項目名の自動生成

#### 手順

1. **「＋」** → **Formula** をクリック
2. プロパティ名を入力（例: `見積金額`）
3. **Edit formula** をクリック
4. 計算式を入力（下記テンプレートをコピペ）
5. **Done**

> **[📸 スクショ]** Formula エディタ画面  
> 保存先: `screenshots/04_formula_editor.png`

#### テンプレート: 現調DB — 項目名（自動生成）

```
concat(
  prop("場所"), " / ",
  prop("工事分類"), " / ",
  prop("作業内容"),
  if(empty(prop("型式・サイズ")), "", " (" + prop("型式・サイズ") + ")")
)
```

#### テンプレート: 現調DB — 見積単価

```
prop("標準単価") * prop("案件").prop("単価補正率")
```

> `案件` の Rollup で補正率を取得している場合:

```
prop("標準単価") * prop("補正率")
```

#### テンプレート: 現調DB — 見積金額

```
prop("見積単価") * prop("数量")
```

#### テンプレート: 見積DB — 消費税

```
round(prop("小計") * 0.1)
```

#### テンプレート: 見積DB — 税込合計

```
prop("小計") + prop("消費税")
```

#### テンプレート: 請求DB — 消費税

```
round(prop("請求金額") * 0.1)
```

#### テンプレート: 請求DB — 税込金額

```
prop("請求金額") + prop("消費税")
```

#### テンプレート: 単価マスターDB — キー（照合用）

```
prop("工事分類") + "_" + prop("作業内容") + "_" + prop("型式")
```

#### Formula の注意点

- プロパティ名は **完全一致**（全角/半角、スペースに注意）
- `prop("名前")` で他プロパティを参照
- Relation 経由: `prop("案件").prop("単価補正率")` 形式
- エラーが出たら Edit formula 画面下部の赤文字を確認

### 2-9. ダッシュボード

**場所**: ワークスペース最上部

#### 手順概要

3. `/column` → **2 columns** を 3 回使い KPI Callout 6 個を配置
4. 各 KPI の下に `/linked` → **Linked view of database** で各 DB をリンク
5. 各 Linked view に Filter / Sort を設定（[dashboard_design.md](./dashboard_design.md) 参照）

#### Linked view の作り方

1. ページ本文で `/linked` と入力
2. **Linked view of database** を選択
3. リンクする DB（例: 見積DB）を選択
4. リンクブロック左上のビュー名をクリック → 名前変更
5. 右上 **「⋯」** → **Filter** / **Sort** / **Layout** を設定

## 第4章: よくある質問

| 質問 | 回答 |
|------|------|
| Select の選択肢を後から追加できる？ | 列ヘッダー → Edit property → Add an option |
| Relation を間違えた | Edit property → リンク先 DB を変更（データは消える場合あり） |
| Formula が `#ERROR` になる | プロパティ名のスペル・全角半角を確認 |
| CSV インポートで文字化け | UTF-8（BOM なし）で保存し直す |
| Unique ID は CSV で設定できる？ | 不可。インポート後に自動採番される |
| 半日で終わらない | 顧客・単価の CSV インポートまで先に完了させ、Relation は翌日でも可 |
