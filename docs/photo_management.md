# 工事写真管理DB — 設計・構築手順

> **TOMS Phase 1.5** — 現調・施工前・施工中・施工後・完成の写真を案件に紐付け  
> 最終更新: 2026-05-31

---

## 1. 目的

現場写真を工程別に整理し、案件単位で一覧・検索できるようにする。

| 写真分類 | タイミング | 用途 |
|---------|-----------|------|
| 現調 | 現場調査時 | 見積根拠・現状記録 |
| 施工前 | 施工開始前 | Before 記録 |
| 施工中 | 作業中 | 進捗・隐蔽部記録 |
| 施工後 | 施工直後 | After 記録 |
| 完成 | 引渡し時 | 完成報告・請求根拠 |

---

## 2. プロパティ定義

| プロパティ名 | Notion型 | 必須 | 説明 |
|-------------|----------|------|------|
| 写真名 | **Title** | ○ | 自動生成推奨（Formula連携） |
| 案件 | **Relation** → 案件管理DB | ○ | 双方向 |
| 案件番号 | **Rollup** | — | 案件 → 案件番号 |
| 顧客名 | **Rollup** | — | 案件 → 顧客名 |
| 写真分類 | **Select** | ○ | 下記選択肢 |
| 場所 | **Select** | ○ | 現調DBと同一選択肢 |
| 撮影日 | **Date** | ○ | デフォルト: 今日 |
| 写真 | **Files & media** | ○ | 複数枚可 |
| 説明 | **Text** | △ | 状況メモ |
| 担当者 | **Select** または **Person** | △ | 撮影者 |
| 現調項目 | **Relation** → 現調DB | — | 該当工事項目へのリンク |
| 作成日時 | **Created time** | — | 自動 |

### 2.1 写真分類（Select）選択肢

```
現調
施工前
施工中
施工後
完成
```

> ユーザー要件の「施工前・施工中・施工後・完成」に加え、Phase 1 の現調写真を統合するため **現調** を含む。

### 2.2 場所（Select）選択肢

現調DB と同一:

```
1階トイレ / 2階トイレ / 廊下 / 脱衣所 / 外壁 / 屋根裏 / 駐車場 / その他
```

## 4. Notion 構築手順（初心者向け・詳細）

### Step 1: 新規データベースを作成

1. 左サイドバー → **現場入力** フォルダを開く（なければ作成）
2. **＋ New page** → タイトル: `工事写真管理DB`
3. 本文で `/table` → **Table - Full page**
4. DB名を `工事写真管理DB` に設定

### Step 2: Title を「写真名」に変更

1. 列 `Name` → **Edit property** → 名前: `写真名`

### Step 3: プロパティを追加

#### 3-1. 案件（Relation）

1. **＋** → **Relation**
2. データベース: **案件管理DB**
3. 双方向: **ON** → 逆方向名: `工事写真`
4. **Done**

#### 3-2. 案件番号（Rollup）

1. **＋** → **Rollup**
2. Relation: `案件`
3. Property: `案件番号`
4. Calculate: **Show original**

#### 3-3. 顧客名（Rollup）

1. **＋** → **Rollup**
2. Relation: `案件`
3. Property: `顧客名`
4. Calculate: **Show original**

#### 3-4. 写真分類（Select）

1. **＋** → **Select** → 名前: `写真分類`
2. 選択肢を追加:

| 選択肢 | 色 |
|--------|-----|
| 現調 | 青 |
| 施工前 | オレンジ |
| 施工中 | 黄 |
| 施工後 | 緑 |
| 完成 | 紫 |

#### 3-5. 場所（Select）

1. **＋** → **Select** → 名前: `場所`
2. 選択肢:

```
1階トイレ
2階トイレ
廊下
脱衣所
外壁
屋根裏
駐車場
その他
```

#### 3-6. 撮影日（Date）

1. **＋** → **Date** → 名前: `撮影日`
2. Default: 新規レコード作成時に手動で今日を入力（Notion は Date の自動デフォルト非対応）

#### 3-7. 写真（Files & media）

1. **＋** → **Files & media** → 名前: `写真`

#### 3-8. 説明（Text）

1. **＋** → **Text** → 名前: `説明`

#### 3-9. 担当者（Select）

1. **＋** → **Select** → 名前: `担当者`
2. TOMS メンバー名を選択肢として追加（例: 智紀、現場A、現場B）

> Person 型を使う場合: **＋** → **Person** → ワークスペースメンバーから選択

#### 3-10. 現調項目（Relation）

1. **＋** → **Relation** → **現調DB**
2. 双方向: **OFF**（単方向でOK）
3. 名前: `現調項目`

#### 3-11. 作成日時（Created time）

1. **＋** → **Created time** → 名前: `作成日時`

### Step 4: 写真名の自動生成（Formula — 任意）

Title を Formula に変更できないため、運用ルールまたは手動入力。  
代替案として **説明** の先頭行に命名規則を統一:

```
{撮影日}_{場所}_{写真分類}
例: 20260531_1Fトイレ_現調
```

### Step 5: ビューを作成

#### 5-1. 案件別ギャラリー

1. **＋ Add a view** → **Gallery** → 名前: `案件別ギャラリー`
2. **Layout** → Card preview: `Page content` または `Property: 写真`
3. **Group** → `写真分類`
4. **Sort** → `撮影日` Descending

#### 5-2. 施工記録ボード

1. **＋ Add a view** → **Board** → 名前: `施工記録`
2. **Group by** → `写真分類`
3. カード表示プロパティ: 案件番号、場所、撮影日、写真

#### 5-3. 今日の撮影

1. **＋ Add a view** → **List** → 名前: `今日の撮影`
2. **Filter** → `撮影日` **is** `Today`

### Step 6: スマホ撮影フォーム

1. **＋ Add a view** → **Form** → 名前: `TOMS 写真撮影`
2. 表示順（ドラッグで並べ替え）:

| 順 | プロパティ | 必須 |
|----|-----------|------|
| 1 | 案件 | ○ |
| 2 | 写真 | ○ |
| 3 | 写真分類 | ○ |
| 4 | 場所 | ○ |
| 5 | 撮影日 | ○ |
| 6 | 説明 | — |
| 7 | 担当者 | △ |

3. フォームURLをスマホホーム画面に追加

## 5. 60 秒フローとの連携

Phase 1.5 のスマホ 60 秒フローでは、現調入力と写真撮影を同時に行う。

### パターン A: 現調DB 経由（推奨・初期運用）

```
クイック入力フォーム
  → 現調DB に写真付きで保存
  → 現調完了後、工事写真管理DB に「現調」として転記
```

### パターン B: 写真DB 直接（写真先行）

```
TOMS 写真撮影フォーム
  → 工事写真管理DB に直接保存（写真分類: 現調）
  → 後から現調DB に項目入力
```

### パターン C: Phase 2 自動連携（将来）

```
現調DB 保存トリガー
  → Automation: 写真を工事写真管理DB に複製
  → 写真分類 = 現調 を自動設定
```

## 7. QNAP 連携（Phase 2 準備）

Phase 2 で QNAP 自動保存する際のフォルダ構成:

```
QNAP/TOMS/{顧客名}/{案件名}/
├── 現調写真/       ← 写真分類 = 現調
├── 施工前/
├── 施工中/
├── 施工後/
└── 完成/
```

ファイル命名規則（Phase 1 踏襲）:

```
{YYYYMMDD}_{場所}_{写真分類}_{連番}.jpg
例: 20260531_1Fトイレ_現調_001.jpg
```
