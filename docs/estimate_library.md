# 見積ライブラリDB — 設計・構築手順

> **TOMS Phase 1.5** — 過去見積の検索・AI単価提案・類似案件検索の基盤  
> 最終更新: 2026-05-31

---

## 1. 目的

| 用途 | 説明 |
|------|------|
| 過去見積検索 | 工事分類・顧客・金額帯で過去の見積をすぐ参照 |
| AI単価提案 | Phase 4 で過去データを学習元として活用（Phase 1.5 では DB 整備） |
| 類似案件検索 | 同じ工事分類・規模の案件を横断検索 |

---

## 2. プロパティ定義

| プロパティ名 | Notion型 | 必須 | 説明 |
|-------------|----------|------|------|
| 見積タイトル | **Title** | ○ | 例: 土浦寮_換気_20260531 |
| 見積番号 | **Text** または **Unique ID** | ○ | 例: EST-0015（見積DBと同一） |
| 案件 | **Relation** → 案件管理DB | ○ | 双方向 |
| 案件番号 | **Rollup** | — | 案件 → 案件番号 |
| 顧客名 | **Rollup** または **Relation** | ○ | 案件経由 or 顧客マスター直接 |
| 顧客区分 | **Rollup** | — | 顧客マスター → 顧客区分 |
| 工事分類 | **Select** | ○ | 現調DBと同一選択肢 |
| 工事項目 | **Text** または **Relation** → 現調DB | △ | 概要テキスト or 項目リンク |
| 見積金額 | **Number** | ○ | 税込 or 税抜（運用で統一） |
| 粗利率 | **Number** | △ | ％表示。例: 35 (= 35%) |
| 提出日 | **Date** | ○ | 見積提出日 |
| 受注結果 | **Select** | ○ | 下記選択肢 |
| 写真 | **Files & media** | △ | 現場参考写真 |
| PDF | **Files & media** | △ | 見積書PDF |
| 元見積 | **Relation** → 見積DB | △ | 原本へのリンク |
| 備考 | **Text** | — | 失注理由・値引き記録など |

### 2.1 受注結果（Select）選択肢

```
受注
失注
保留
見積のみ（未回答）
```

### 2.2 工事分類（Select）選択肢

Phase 1 の現調DB と **完全一致** させる:

```
換気 / 照明 / コンセント / スイッチ / 分電盤 / エアコン / 防犯カメラ / LAN / Wi-Fi / アンテナ / インターホン / EV / その他
```

## 3. ビュー構成

| ビュー名 | 種類 | 用途 | 主な設定 |
|---------|------|------|---------|
| 全件一覧 | テーブル | PC管理 | 提出日降順 |
| 工事分類別 | ボード | 分類ごとの見積履歴 | Group by: 工事分類 |
| 受注実績 | テーブル | 受注案件のみ | Filter: 受注結果 = 受注 |
| 失注分析 | テーブル | 失注理由の確認 | Filter: 受注結果 = 失注 |
| 類似検索 | テーブル | 分類+金額帯検索 | Filter: 工事分類 + 見積金額 |
| ギャラリー | ギャラリー | 写真付き見積一覧 | Cover: 写真 |

## 4. Notion 構築手順（初心者向け・詳細）

### Step 1: 新規データベースを作成

1. Notion 左サイドバー → **見積・請求** フォルダ（なければ **＋ New page** で作成）
2. フォルダ内で **＋ New page**
3. ページタイトル: `見積ライブラリDB`
4. 本文で `/table` と入力 → **Table - Full page** を選択
5. データベース名が `見積ライブラリDB` になっていることを確認

### Step 2: Title プロパティの名前変更

1. 列名 `Name` をクリック → **Edit property**
2. 名前を `見積タイトル` に変更 → **Done**

### Step 3: 各プロパティを追加

テーブル右上 **「＋」** をクリックし、以下を **上から順に** 追加する。

#### 3-1. 見積番号

1. **＋** → **Text** を選択
2. プロパティ名: `見積番号`
3. **Done**

#### 3-2. 案件（Relation）

1. **＋** → **Relation** を選択
2. 検索: `案件管理` → **案件管理DB** を選択
3. 双方向: **ON**
4. 逆方向のプロパティ名: `見積ライブラリ`（自動入力でOK）
5. **Done**

#### 3-3. 案件番号（Rollup）

1. **＋** → **Rollup** を選択
2. プロパティ名: `案件番号`
3. Relation: `案件`
4. Property: `案件番号`
5. Calculate: **Show original**
6. **Done**

#### 3-4. 顧客名（Rollup）

1. **＋** → **Rollup**
2. Relation: `案件`
3. Property: `顧客名`（案件管理DBの Relation 先）
4. Calculate: **Show original**
5. 名前: `顧客名`

> Rollup で顧客名が表示されない場合: 案件管理DB の `顧客名` が Relation 型であることを確認。

#### 3-5. 顧客区分（Rollup）

1. **＋** → **Rollup**
2. Relation: `案件`
3. Property: `顧客区分`
4. Calculate: **Show original**

#### 3-6. 工事分類（Select）

1. **＋** → **Select**
2. 名前: `工事分類`
3. **Edit property** → **Add options** で以下を1つずつ追加:

```
換気
照明
コンセント
スイッチ
分電盤
エアコン
防犯カメラ
LAN
Wi-Fi
アンテナ
インターホン
EV
その他
```

4. 色は任意（分類ごとに色分け推奨）

#### 3-7. 工事項目（Text）

1. **＋** → **Text**
2. 名前: `工事項目`
3. 例: `1Fトイレ 換気交換 φ100 × 2 / 廊下 照明交換 シーリング × 2`

#### 3-8. 見積金額（Number）

1. **＋** → **Number**
2. 名前: `見積金額`
3. Number format: **Yen**（円）

#### 3-9. 粗利率（Number）

1. **＋** → **Number**
2. 名前: `粗利率`
3. Number format: **Number**（値は 35 = 35% と運用）

#### 3-10. 提出日（Date）

1. **＋** → **Date**
2. 名前: `提出日`
3. Include time: **OFF**

#### 3-11. 受注結果（Select）

1. **＋** → **Select**
2. 名前: `受注結果`
3. 選択肢を追加:

| 選択肢 | 色（推奨） |
|--------|----------|
| 受注 | 緑 |
| 失注 | 赤 |
| 保留 | 黄 |
| 見積のみ（未回答） | 灰 |

#### 3-12. 写真（Files & media）

1. **＋** → **Files & media**
2. 名前: `写真`

#### 3-13. PDF（Files & media）

1. **＋** → **Files & media**
2. 名前: `PDF`

#### 3-14. 元見積（Relation）

1. **＋** → **Relation**
2. 検索: `見積` → **見積DB** を選択
3. 双方向: **ON**
4. 逆方向名: `ライブラリ登録`

#### 3-15. 備考（Text）

1. **＋** → **Text**
2. 名前: `備考`

### Step 4: ビューを作成

#### 4-1. 工事分類別ボード

1. 左上ビュー名横 **「＋ Add a view」**
2. **Board** → 名前: `工事分類別`
3. **Group by**: `工事分類`
4. **Sort**: `提出日` → Descending

#### 4-2. 受注実績ビュー

1. **＋ Add a view** → **Table** → 名前: `受注実績`
2. **Filter** → **Add filter**
3. `受注結果` **is** `受注`
4. **Sort**: `提出日` Descending

#### 4-3. 類似検索ビュー

1. **＋ Add a view** → **Table** → 名前: `類似検索`
2. 使用時に Filter を都度設定:
   - `工事分類` **is** `換気`（例）
   - `見積金額` **greater than** `100000`
   - `見積金額` **less than** `300000`

### Step 5: 見積DB からの登録運用

見積提出後、ライブラリへ手動登録（Phase 2 で自動化予定）:

1. **見積DB** → 対象見積を開く
2. **見積ライブラリDB** → **New**
3. 以下を転記:

| ライブラリ項目 | 転記元 |
|--------------|--------|
| 見積タイトル | 見積名 |
| 見積番号 | 見積番号 |
| 案件 | 同じ案件 |
| 工事分類 | 主要項目の分類（手動） |
| 工事項目 | 現調項目の概要 |
| 見積金額 | 税込合計 |
| 提出日 | 作成日 |
| PDF | 見積書PDF |
| 元見積 | 該当見積レコード |

4. 受注/失注が確定したら **受注結果** を更新

## 5. 検索・活用シナリオ

### 5.1 過去見積検索

```
営業ダッシュボード or 見積ライブラリDB
  → 類似検索ビュー
  → 工事分類 = 換気
  → 見積金額 50,000〜150,000
  → 提出日降順で参照
```

### 5.2 類似案件検索

1. 新規見積作成前に **工事分類別** ボードを開く
2. 同じ分類の過去案件を確認
3. 受注案件の金額帯を参考に見積単価を決定

### 5.3 AI単価提案（Phase 4 連携用データ要件）

Phase 1.5 時点で以下を蓄積しておく:

| 項目 | 用途 |
|------|------|
| 工事分類 + 工事項目 | 類似工事の特定 |
| 見積金額 + 粗利率 | 適正価格帯の算出 |
| 受注結果 | 受注率の高い価格帯分析 |
| 顧客区分 | 顧客別価格戦略 |

---

## 6. 既存データ移行

Phase 1 運用済みの見積がある場合:

1. **見積DB** → 全件表示
2. 1 件ずつ **見積ライブラリDB** に登録（Step 5 参照）
3. 受注結果は案件管理DB の状態から判定:

| 案件状態 | 受注結果 |
|---------|---------|
| 受注 / 施工完了 / 請求済 | 受注 |
| 見積提出（その他） | 見積のみ（未回答） |
| 見積撤回 | 失注 |
