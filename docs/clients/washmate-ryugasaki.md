# ウォッシュメイト龍ヶ崎店（WASHMATE001）顧客カルテ

お客様の入口は `https://tisly.jp/customer` に固定する。社内の `/app` には、この店の詳細設定パネルを出さない。

## 識別子

顧客コードは `WASHMATE001`。ログイン ID は `wm-ryougasaki001`。パスワードは台帳とソースに平文で残さない。Security の現場 ID は `SEC-JP-RYUGASAKI-001`。HOME の参照 ID は `HOME-JP-RYUGASAKI` だが、有効モジュールは Security のみで、TiSLY HOME とカメラは付けない。主装置は `rp2350-ryugasaki-main-01`。

## 端子

DI1 はバックヤード入口、DI2 は両替機、DI3 はバックヤードの人感センサー。入力が反応しても出力は動かさない。通知だけ送る。DO1 は回転灯、DO2 はベル。どちらもお客様が確認した遠隔操作とテストだけが動く。

DI1 と DI2 の確定は 100ms。DI3 はお客様が 1 秒から 30 秒で選べる。初期値は 1 秒。回転灯とベルの作動は 5 秒から 180 秒。初期値は 15 秒。保存はすぐ行い、実機は命令の取得周期で同じ秒数を受け取る。

## お客様画面

`/customer` の TiSLY Security に詳細設定を出す。人感の確定時間、回転灯の時間、ベルの時間をスライダーで変える。回転灯テストとベルテストは、「本当にテスト作動させますか？」の確認のあとだけ送る。豊島邸や板橋自宅の点灯時間帯カードは、この店では出さない。

実機は DHCP を最大5秒で打ち切り、予備 IP `192.168.1.236` へ戻す。ウォッチドッグは LAN 初期化のあとで有効にし、通信は3秒で諦める。GPIO が不正でもその端子だけ飛ばす。初期化に失敗したら約10秒後に最初からやり直す。通信が届くまでランプは青、失敗が続いたら赤点滅、届いたら緑点滅。

実機は W5500 や DHCP が失敗しても予備 IP `192.168.1.236` で続ける。メインループの例外は約10秒待って同じループを再開し、再起動はしない。通信エラーは赤点滅、オンラインは緑点滅。お客様の更新ボタンは安心ステータスの1つだけで、押すとキャッシュを使わず描き直す。

お客様の Security 先頭に、共通の安心ステータスを出す。稼働、最新ハートビート、盤内温度、更新状態。実機は起動直後に心拍を送り、その後は300秒。失敗したら10秒待って再試行し、監視は止めない。

お客様の安心ステータスには版番号を出さない。「最新状態です」か「更新があります（自動更新待機中）」だけを出す。この店の目標版は `1.2.34`。豊島邸の目標版 `1.2.29` や板橋の `1.6.6` とは別。OTA は龍ヶ崎店のスクリプトだけを配る。

2026-10-27 以降、この店の目標版は `1.2.40`。DI1 と DI2 はプルアップで、開いた状態とショートした状態の両方を 100ms 確定してから通知する。送信に失敗した変化は捨てずに再送する。反応と復帰のどちらも Web Push と履歴に残す。回転灯とベルはこれまでどおり連動しない。社内の遠隔配信ボタンは、実機が `1.2.39` 以下ならこの版を配る。
